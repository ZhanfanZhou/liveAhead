# 鲜知 · 本地生活 爆品&优惠先知方案

## 1. why AI

用户的需求拆开就是三个动作：**及早发现或预测**全网新上架的优惠或火爆的商品、**匹配给最可能买的人并帮助完成购买行为**。

**及早发现 提前预测**
- 传统：羊毛群、人工整理、达人探店、APP 分发。慢、覆盖窄、噪音大、不可规模化，而且"发出来时往往已经火了"。
- AI 能够实时监控，提前收集社交媒体等周边商家/网络红人动态信息，或根据商品历史习惯，提前预测优惠信息

**个性化推荐&执行**
- AI：用 LLM 维护"活的"用户画像做千人千面排序；用 Agent 长期盯品、到点提醒、甚至（授权后）自动下单。

### 为什么现在没人做成：每家只占了链条的一两环

|------|:---:|:---:|:---:|:---:|:---:|:---:|
| 平台自身（美团神券 / 抖音团购 / 携程） | ✅ | △ | ❌ | △ | ✅ | ❌（推已验证爆款＋投流） |
| 优惠聚合（什么值得买 / 省钱快报 / Dealmoon） | ❌（偏实物电商） | △（人工/众包爆料） | ❌ | ❌ | △ | ✅ |
| 比价工具（慢慢买等） | ❌ | ❌ | ❌（只看历史价） | ❌ | ✅ | ✅ |

### 2.2 对话式盯品

像在跟**一个懂行的本地生活私人买手**对话。自然语言下指令，翻译成一个**持久化的监控 Agent**（一个"盯品任务"）。

```
你：帮我盯朝阳区新开火锅店的开业券，5 折以下、预测会火的，
    提前一天提醒我。
鲜知：好，已建立盯品任务 🎯
     · 范围：朝阳区 · 新开（≤30 天）· 火锅
     · 条件：折扣 ≤5 折 且 爆火分 ≥75
     · 动作：预测爆发前 1 天提醒
     当前命中 2 家，未来新店会自动纳入。要不要只看连锁品牌？

你：只要连锁的，预算调到 200。
鲜知：已更新 ✅ 仅连锁品牌、单券 ≤¥200。
```

### 2.3 Agent 授权抢购

盯品任务可升级为"自动行动"。Agent 的"判断"由模型做（这单值不值得抢），执行由工具完成，**下单前的授权由你定义的规则把关**。三档模式由用户自选：

| 模式 | 行为 |
|------|------|
| 🔔 仅提醒 | 到点推送，你手动操作 |
| 🛒 自动加购待确认 | 自动锁单/加购，发一条确认请求 |
| 🤖 条件全自动 | 满足预设规则（如"分>90 且 <300 元"）直接下单 |

- **风控框架**：单笔/单日额度上限、白名单品类、可撤销窗口、human-in-the-loop 兜底、异常熔断。
- ⚠️ **落地标注**：全自动下单涉及代操作平台账号与代付，合规与技术风险最高（见第 4 节）。理想态全自动；落地大概率先降级为"一键直达 + 智能预填"。

### 3.1 数据层

数据层是**长期记忆**，把全网零散的商品、商家、品牌、达人、用户、商圈、时间，连成一张随时间生长的**关系网**。产品可以**按关系查同类产品、按时间看历史趋势**，提前预测优惠、火爆产品

**图里存了什么：**

| 存什么 | 含义 | 例子 |
|---|---|---|
| **节点（名词）** | 商品/券、商家/门店、品牌、品类、商圈、达人、用户 | 每个节点挂自己的档案：商家挂"开了多久·历史新品表现"|
| **边（关系，带权重＋时间戳）** | 同商圈/同品类/同品牌、达人探过、用户收藏/抢过、价格历史、**"这家像历史上的那家"（类比边）** | 类比边是预测层最依赖的——爆火判断本质就是"和谁像" |
| **节点随时间变的三样东西** | ① 多模态向量（图文/视频语义，用来"找相似"）② 时序曲线（价格/热度/销量逐日变化，用来看动量、回测）③ 结果标注（后来到底火没火、几天回涨——模型的"答案册"） | 再加上挂在商圈/时间上的**外部上下文**（节假日/天气/演唱会），用来解释爆发节奏 |


### 3.2 信息感知层：感知什么 + 怎么感知

**A. 信号来源：**

| 信号层 | 具体信号 | 价值 |
|------|------|------|
| 供给侧（商品本身） | 新上架商品/SKU、新开门店、新券、套餐变更、**价格/库存变化** | 信息差的"原子事件" |
| 内容 / 前导侧 | 探店达人、网红、KOL 的动态：去了哪家新店、发了什么、互动量 | **领先指标**——达人先探、大众后到，给我们提前量 |
| 需求侧（真实意图） | 餐厅到店/排队人数、预订量、搜索量变化、**地图导航/路线规划频次上升** | 早期动量的来源；导航去某店 ≈ 强购买意图，是最干净的需求信号 |
| 环境 / 上下文 | 节假日、天气、本地活动/演唱会/展会、社媒热点 | 解释与校准爆发节奏 |

> ⚠️ 越靠"需求侧/前导侧"的信号越值钱，也越难拿（到店、导航、预订数据基本握在平台/地图厂商手里），落地高度依赖 B 端合作，见第 4 节。理想态假设可获取。

**B. 感知方法**

- **变更检测（diff）是核心**：维护全网新品/新店/新券的快照，定时比对，只对「**新出现** / 价格变 / 库存变」产出事件——不全量抓、只抓"变化"，这才是信息差的原子事件。
- **采集方式**：
  - **定向 B 端 API 合作**（最干净）：与平台开放平台、SaaS 收银/排队系统、地图厂商合规对接，拿一手数据。
  - **公开数据采集 / 爬虫**（现实主力）：分布式采集公开页面 ＋ 反反爬。⚠️ 难度与合规风险最高。
  - **用户侧众包**：浏览器插件 / App 在用户授权下回传其浏览到的商品页（类"什么值得买"路径），边缘分布、天然合规。
  - **达人 / MCN 共建**：达人上报探店，换取选题情报（与第 5 节商业化打通）。
  - **第三方数据**：地图导航热度、POI 客流、社媒舆情 API。
- **Agent 化采集调度**：采集本身就是一组**定时任务 Agent**——每个数据源/商圈一个采集 Agent，按价值**动态调频**：高潜商圈/品类加密监控（分钟级），长尾降频（天级）。


### 3.3 预测层：爆火&优惠预测

**① 内容内生信号（冷启动唯一可用、AI-native 内核）**
- 处理什么数据：感知层已抽好的结构化字段（真实折扣、门槛、套餐、稀缺性）＋ 图文视频本身。
- 怎么算：一半走可计算特征，一半让 LLM/VLM **zero-shot 直接给"诱人度"评分**（无需任何行为数据）。子信号：折扣真实力度、门槛友好度、稀缺性、品类当下热度、品牌势能、内容质量、价格锚点合理性。

**② 类比同类商品历史信号/规律**
- 定期取出过往热门商家的**折扣曲线**，预测最近可能的动态。如淡季某地区的机票&酒店，周期性活动的热门餐厅等。
- 针对新店则结合同/邻品类 × 同/邻商圈 × 相近价位做判断

**③ 早期动量信号**
- 最近几天的高频变量——浏览/收藏增速、达人探店是否出现、社媒提及加速度、地图导航频次、搜索量。如"同品类同时段正常新品基线"比，超出 N 个标准差 意味强动量；或出现达人探店出现等信号。

**三类信号动态加权融合**：起初冷启动阶段依赖已有数据设置经验值，随用例增加模型自我修正

**可解释性**
- **结构化归因**：模型不只吐总分，而是给**三路分解**（内容 X 分 / 类比 Y 分 / 动量 Z 分）＋ 每路的关键证据，LLM 再把归因 ＋ 检索到的历史先例写成自然语言。
- **给用户看什么（三层渐进，对应 2.1 卡片）**：
  1. **一句话理由**（卡片默认）：只给最强那条证据——"同商圈 2 家同价位川菜 2 周售罄，这家门槛更低"。
  2. **可展开归因面板**：三路信号条形图 ＋ 证据明细（内容：真 3.9 折/可叠加；类比：列出 2 家历史相似店 ＋ 其爆发曲线缩略图；动量：收藏增速曲线）。
  3. **不确定性显式化**：用区间（窗口 5–9 天）而非点估计，标注置信度，错了认错。
- **怎么通过交互体现（衔接"可解释 → 可对话"）**：
  - 卡片"为什么会火"可展开；用户可**追问**（"凭什么说门槛低？"→ LLM 引详情页原文小字）。
  - **历史先例可点开核查**："参考了这 2 家" → 点进去看它们当初的真实爆发轨迹，信任来自可核查、而非口说。
  - **事后复盘仪表盘**：到期回看"我们说会火、结果如何"，公开命中率，长期建立信任。

- ⚠️ **落地标注**：高质量训练数据靠"上架 → 是否真火"的标注闭环积累；冷启动期准确度有限，必须用透明置信度管理预期（见第 4 节）。

### 3.4 个性化层：千人千面的"时机推荐"

- 推荐的不是"商品"，而是 **"商品 × 时机 × 给谁"** 的三元组。
- **用户画像（LLM 构建并持续维护的"活画像"）**：口味、常去商圈、预算敏感度、消费节奏、同行人结构。能读懂语境——"这人最近在搜婚礼" → 推蜜月酒店早鸟。
- **排序公式**：`全局爆火分 × 个人相关性` → 个性化推荐流。

### 3.5 行动层：云端大脑 + 个性化订阅 的多 Agent 架构

**核心架构决策**：重活（发现 → 打分 → 挖优惠）在**云端大脑跑一次、服务所有人**；用户侧只做**轻量订阅**与**按需对话**。分三层部署：

**A. 云端大脑结合用户消息订阅模式**
把"发现 → 打分 → 挖优惠"做成一条全局流水线，产出所有人共享的**「已分析爆款池」**（结果写回信号图谱）。

| Agent | 作用域 | 职责 | 模型档位 |
|---|---|---|---|
| 采集 Agent | 全局 | 按商圈/品类定时抓取（见 3.2），产出原子事件 | 轻量 |
| 全局 Watcher（探测/分诊） | 全局 | 接住新事件，去重、滤垃圾、按潜力分诊，决定谁值得深算 | 规则/轻量 |
| 预测 & 评估 Agent | 全局 | 对高潜事件跑爆火预测＋优惠分析（见 3.3），打分写回图谱 | 推理模型 |
| 编排 Orchestrator | 全局 | 调度这条流水线的优先级/并发/调频（高潜加密、长尾降频） | 推理模型 |

> 关键：这层**一次分析、服务所有人**——成本只跟商品量相关、与用户数无关，因此可控。

**B. 个性化订阅层（每用户 · 轻量）**
用户不跑重型 Agent，只**订阅**爆款池的结果。

- **个性化分发**：爆款池 × 用户画像 → 个性化雷达推荐流（默认、被动收）。本质是轻量匹配/排序，不是 per-user agent。
- **盯品订阅（Standing Subscription）**：用户建的盯品任务 ＝ 注册在爆款池上的一条**持久化过滤条件（standing query）**，新结果流过即匹配，命中才触发——而非常驻一个 LLM Agent 空转。
- **个人 Executor ＋ 风控 Guardrail**：仅当某用户订阅命中且开了授权档，才为该用户起**一次性**执行（下单/加购），过 Guardrail（额度/白名单/可撤销/人审），用完即走。

**C. 按需对话层（用户主动发起才起）**
- **对话 Agent**：用户主动搜索/对话时临时拉起一个会话级 Agent——理解意图 → 查爆款池 → 答疑与追问 →（可选）把需求编译成盯品订阅注册到 B 层 → 会话结束即释放。不常驻。

**调度方式**：① 云端大脑是**事件驱动的常驻流水线**（采集→分诊→预测，按潜力动态调频）；② 个性化层是**数据驱动的轻量匹配**（新结果流过 → 匹配画像与订阅条件 → 分发）；③ 对话层是**请求驱动的临时实例**（来一个会话起一个、结束释放）。

**用户触发方式**：① **被动订阅（默认）**——什么都不做，个性化雷达流持续推来（发现型）；② **主动对话**——用嘴查/下盯品指令，对话 Agent 处理、可沉淀为订阅；③ **盯品 ＋ 授权抢购**——订阅命中后按三档（仅提醒/加购待确认/全自动，见 2.3）行动。

**流程图：**

```
【云端大脑 · 全局常驻】（成本随商品量，与用户数无关）
  采集Agent ──新事件──▶ 全局Watcher(去重/分诊) ──高潜──▶ 预测&评估Agent(打分/挖优惠)
                            ▲ Orchestrator 调度并发/调频                  │ 写回
                                                                         ▼
            ┌──────────────────────────────────────────────────────────────┐
            │             信号图谱 ＝ 已分析「爆款池」（全员共享）              │
            └──────┬────────────────────────┬───────────────────────┬───────┘
        被动·默认 │                 盯品命中 │                主动发起 │
                  ▼                          ▼                        ▼
       【个性化分发·每用户轻量】       【盯品订阅触发】          【按需对话Agent】
        池 × 画像 → 雷达流            standing query 命中       查池/答疑/追问，可
              │                            │                   沉淀为盯品订阅、用完释放
              ▼                            ▼
         用户被动收看         授权档?─全自动→个人Executor→Guardrail→下单→汇报
                                       └─仅提醒/加购待确认→推送给用户
```

- ⚠️ **落地标注**：个人 Executor 的自动下单（代操作账号 ＋ 代付）合规/技术风险最高，落地大概率先降级为"一键直达 ＋ 智能预填"，见第 4 节。

### 3.7 端到端示例（把五层串起来看）

**示例 1 · 用户主动盯品 + 授权抢购（主动发起路径）**

```
背景：老B 对话下令"盯朝阳川菜开业券，5 折内会火的，≤300 元全自动抢"。
     对话Agent 编译成盯品订阅（范围:朝阳·川菜·新开 / 条件:≤5折且爆火分≥75 /

```

## 4. 落地难点 & 风险标注（理想态 vs 落地的诚实差距）

按要求把"理想很美但落地很难"的地方明确标注。难度用 ⚠️ 数量表示。

| # | 难点 | 风险等级 | 理想态 → 落地差距 |
|---|------|:---:|------|
| 1 | **数据获取** | ⚠️⚠️⚠️ | 美团/抖音等无开放 API、强反爬，商品数据是其核心资产。**这是整个产品的生死线。** 落地需多管齐下：开放平台/导流分成合作、合规采集、用户侧浏览插件贡献数据、达人共建。理想态假设可获取。 |
| 2 | **自动下单的合规与技术** | ⚠️⚠️⚠️ | 代操作平台账号 + 代付，触及平台 TOS、支付合规、账号安全。落地大概率降级为"一键直达 + 智能预填 + 提醒"。 |
| 3 | **平台对抗** | ⚠️⚠️ | 你在帮用户"反平台信息差"，平台可能封禁/对抗。商业上需找到不直接对立的姿态（见第 5 节"商家端冷启动加速器"，把对立转成合作）。 |
| 4 | **预测准确度与信任** | ⚠️⚠️ | 喊火没火、喊涨没涨会损伤信任。冷启动期准确度有限。对策：置信度全程透明、错了认错、持续校准、用"窗口区间"而非"精确点"表达。 |
| 5 | **信号图谱构建（实体对齐）** | ⚠️⚠️ | 同一家店/品牌在美团、点评、抖音上名称、地址、门店数常对不上，叠加海量脏数据，要把它们对齐成一个干净节点本身就很重；图谱连错，3.1 的"查亲戚做类比"就全盘皆错。对策：多源实体对齐（地理围栏＋名称＋证照模糊匹配）、关系按置信度加权、只对高价值节点做人工校验。 |
| 6 | **海量商品的算力与召回取舍（云端大脑）** | ⚠️⚠️ | 全网千万级商家商品，**不可能逐个跑多模态深度理解**，必须用 3.2-C 的廉价漏斗层层筛。省了成本，代价是**可能漏掉"毫无早期信号的潜力新品"**（召回风险）。这是成本 vs 召回的长期权衡，无法一次解决：落地的妥协是"宁可漏长尾、绝不漏高潜商圈/品类"，再用便宜的哨兵信号（达人探店/导航陡增）兜底升频，并持续用结果标注回测漏报率、反复调阈值。 |
| 7 | **真假折扣对抗** | ⚠️ | 商家会先涨后降对抗识别，需要可靠价格历史（又回到难点 1）。 |
| 8 | **多模态理解成本** | ⚠️ | 海量商品做 VLM/LLM 理解成本高。对策：3.2-C 漏斗只深算少数高潜候选 ＋ 3.6 模型梯队 ＋ 缓存复用。 |
| 9 | **隐私与合规** | ⚠️ | 用户画像、代操作授权、数据来源合规。需要清晰的授权链路与数据最小化。 |

## 5. 商业化与运营策略

### 5.1 目标用户分层与变现

| 人群 | 主要诉求 | 最常用的功能 | 变现方式 |
|------|---------|------------|---------|
| 🛒 大众消费者 | 省心、别错过身边好店好券 | 个性化雷达流 | CPS / 佣金（导流分成），规模化但低 ARPU |
| 🎯 精明玩家 / 代购 | 极致信息差、速度、套利 | 雷达 + Agent 抢购 | **订阅制（高 ARPU）**，付费意愿最强 |
| 🎬 探店达人 / 创作者 | 第一时间抓爆款选题 | 爆火预测榜单 | **B 端合作**：向达人推荐高潜选题、提供内容素材生成工具、MCN/带货分成 |

- **达人合作（原"达人工作台"下沉为商业化手段，不进产品主体）**：把爆火预测榜单作为"选题情报"卖给/合作给探店达人与 MCN——他们既是付费方，也是把鲜知发现的爆品分发出去的渠道。
- **商家端「新品冷启动加速器」（化敌为友的关键 B 侧收入）**：反过来向商家收费——帮其新品/新店在鲜知精准触达高潜用户、加速起量。这既开辟 B 端收入，又把"反平台"姿态转成"帮商家、与平台共赢"的合作姿态，缓解第 4 节的平台对抗风险。

### 5.2 冷启动与数据飞轮

**鸡生蛋难题**：预测模型需要历史数据，但启动时没有。两条腿同时 bootstrap：
- **模型冷启动**：先用 LLM **zero-shot** 预测（不需训练数据即可上线）+ 抓取历史已爆案例做 few-shot/弱监督，先跑起来，再逐步训练专用模型。
- **用户冷启动（决定了上线节奏）**：先攻 🎯玩家 + 🎬达人——意愿最强、最能忍受粗糙 UX，而且**他们的抢购行为与探店内容本身就是高质量信号**，正好反哺模型。模型变准后再放量给 🛒大众消费者吃红利。即 *"为工具而来，为网络而留"*。

**数据飞轮（护城河）**：
```
用户盯/抢/忽略 → 模型更准 → 推荐更准 → 更多用户 → 更多行为反馈
                  越用越聪明，后来者难以追赶
```

### 5.3 上线节奏

| 阶段 | 主攻人群 | 目标 |
|------|---------|------|
| Phase 1 | 玩家 + 达人 | 攒行为信号与内容，bootstrap 预测模型，验证命中率 |
| Phase 2 | 大众消费者 | 模型够准后放量，靠 CPS/订阅规模化变现 |
| Phase 3 | 商家端 + 生态 | 新品首发合作、交易闭环、本地生活全品类 super app |

## 6. 产品效果评估指标

### 6.1 北极星指标

**北极星 ＝ 有效抢先次数（Successful Early Catch）／人·月**

> 定义：用户经鲜知推荐 → 在「实际爆发或涨价之前」完成购买 → 且事后被客观验证「确实火了／确实是真优惠」的成功次数。

选它的原因：这一个数同时编码了全链路四个条件——**发现得早**（提前量>0）、**预测得准**（事后验证真火/真省）、**匹配对人**（该用户真的买了）、**真优惠**（净省为正）。任意一层掉链子，这个数都涨不上去，因此它逼着整条流水线一起变好，而非单点刷量。

- **价值量化（North Star 的金额口径）**：累计为用户**净省金额** ＋ 抢到的**稀缺机会数**（早鸟/限量/售罄前锁单）。
- **护栏指标（Guardrail，防止为冲量滥推）**：**误报打扰率** ＝ 喊火没火/喊涨没涨带来的无效打扰占比。北极星涨、护栏不破，才算健康增长。

### 6.2 分层过程指标（沿流水线逐层体检，多为先行指标）

| 流水线层 | 关键指标 | 口径 / 目标 | 先行▶ /滞后◀ |
|---|---|---|:---:|
| ⓪① 感知·数据 | **信号覆盖率** | 捕获新品/新券事件 ÷ 抽样普查的真实全量；分平台/商圈/品类看 | ▶ |
| | **捕获时延（Freshness）** | 真实上架 → 系统入库 的中位/95 分位延迟，目标**分钟级**（提前量的物理上限） | ▶ |
| | **结构化抽取 F1** | VLM/LLM 抽的折扣/门槛/套餐/价格 vs 人工标注 | ▶ |
| | **噪音率 / 去重率** | 垃圾事件、重复事件占比（越低越好） | ▶ |
| ② 预测 ★ | **预测 Precision / Recall** | 在"真火"客观定义下（见 6.6），喊准了多少、漏了多少 | ◀ |
| | **排序质量 AUC / Top-K 命中** | 爆火分对"谁会爆"的排序能力 | ◀ |

| | **打扰护栏：划走/屏蔽/关推送率** | 单位有效推荐附带的打扰条数（越低越好） | ▶ |
| ④ 行动 | **盯品命中有效率** | 触发的盯品中用户认可"正是我要的"比例 | ▶ |
| | **提醒时机准确率** | 提醒落在最佳抢购窗口内的比例（早了忘、晚了抢不到） | ▶ |

### 6.3 用户价值与留存（结果指标·滞后）

- **省钱/抢到**：人均净省金额、抢到的稀缺机会数（北极星价值口径下沉到人）。
- **留存**：D1/D7/D30 留存、活跃盯品任务存活数、周活跃"抢购"用户数（比单纯活跃更贴近核心价值）。
- **信任**：NPS、"对预测的信任评分"、3.3 事后复盘仪表盘的**查看率与认可率**（公开命中率 → 长期信任）。

### 6.4 商业化指标（对应 5.1 分层变现）

| 人群 | 关键指标 |
|---|---|
| 🛒 大众 | CPS 导流 GMV、导流转化率、ARPU（规模大、单价低） |
| 🎯 玩家/代购 | **订阅转化率、续费率、付费 ARPU**（付费意愿最强，核心收入） |
| 🎬 达人/MCN | 选题**采纳率**、内容产出量、带货分成 GMV |
| 🏪 商家端 | 冷启动加速器签约数、新品起量提升（vs 无鲜知对照组） |
| 健康度 | **LTV / CAC**、毛利率（受多模态理解成本牵制，关联难点 8） |

### 6.5 数据飞轮 & 模型迭代指标（护城河是否在转）

- **标注闭环速度**："上架 → 是否真火"标注的积累速率——决定模型多快变准（呼应 5.2 飞轮）。
- **迭代增益曲线**：每个版本预测 Precision/Recall/校准 的提升幅度，及边际收益是否仍为正。
- **放量 Gate（关联 5.3）**：设定"预测准确率 ＋ 校准达到 X、提前量中位 > Y 天"为硬门槛，达标才从玩家/达人放量给大众——把指标变成上线节奏的开关，而非事后汇报。

### 6.6 评估方法与本产品三个特有难点

**方法**：
- **A/B ＋ Holdout 对照组**：留一组不推，测**增量**而非表面转化（解决归因）。
- **离线回测（Backtest）**：用历史"已爆/没爆"案例集重放，离线算 Precision/Recall/Lead Time，迭代不必等线上。
- **预测台账 ＋ 延迟结算**：每条预测进台账，到爆发窗口结束再回收真值结算——即 3.3 事后复盘仪表盘的工程化。
- **人工抽检**：感知抽取层用人工标注校准 F1。

**本产品特有的评估难点**：

| # | 难点 | 级别 | 说明与对策 |
|---|------|:---:|------|
| 1 | **归因难** | ⚠️⚠️ | 用户本来就要买 vs 鲜知促成？只看转化会高估价值。必须靠 holdout 对照与反事实测增量。 |
| 2 | **"真火"需统一客观定义** | ⚠️ | 否则 Precision/Recall 无意义。建议口径：实际销量/售罄速度/价格回涨/热度峰值**超同类新品基线 N 个标准差**。 |
| 3 | **延迟 ＋ 自我实现预言** | ⚠️⚠️ | ①对错延迟数天~数周 → 靠预测台账长周期结算；②规模大后"我们推了 → 它才火"会自证预言，需用对照组区分**"预测准"与"被我们带火"**（后者其实是商家端价值，但会污染预测准确率评估）。 |
| 4 | **冷启动期指标不可信** | ⚠️ | 样本少、置信区间大，早期指标只作趋势参考，对外配合 5.2 透明置信度管理预期。 |

> 这套指标一体两面：对外是**信任承诺**（公开命中率与复盘，呼应 3.3）；对内是**迭代仪表盘 ＋ 放量开关**（呼应 5.3）。北极星定方向、过程指标定问题出在哪一层、商业指标定能否规模化。
